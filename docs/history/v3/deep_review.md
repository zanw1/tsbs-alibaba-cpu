# 独立数据集项目深度审查

日期：2026-09-07。原审查对象：`dataset_research` 的 v2 构造器、验证器及 v1 输入依赖。当前交付：独立项目 `alibaba_tsdb_dataset`，数据格式版本 3。

## 审查结论

原工具目录可在原机器上使用，但不具备独立项目的构造闭环；其验证也不足以证明每个原生指标与 CSV 一致。本次已经脱离原项目建立包、CLI、依赖锁和独立数据文件，并用源数据验证代替仅比较生成物之间的一致性。

下面的缺陷说明的是旧验证能证明什么，不表示旧数据已经发生错误。新格式已重新构造并从原始输入核验。

## 主要发现与处理

| 优先级 | 旧问题与触发条件 | 可观察证据 | 本次处理 |
|---|---|---|---|
| P1 | 原生内存、网络等非 CPU 指标没有对照原始 CSV；仅查键、CPU、缺失数量 | 旧 `verify_files` 在无原始字段对照的夹具中可接受任意范围内的内存值；新测试将 92 改为 99 后必须失败 | 新验证重新读取 CSV，对七个指标值与 NULL 位置逐一比较 |
| P1 | 两个配对文件同时改变辅助列，可以继续相互一致 | 新独立测试同时修改两侧 `usage_system`，验证拒绝 | 两侧均对照原始 TSBS 参考 |
| P1 | 查询目录为空仍可获得文件验证通过 | 旧验证四个规模的空 JSONL 夹具全部返回 passed；新测试明确拒绝 | 根据已声明的工作负载版本和种子重建预期目录，检查数量、SQL、参数和形状 |
| P1 | 原生版继承有效 CPU 子集，未来窗口会丢失 CPU 缺失但其他指标存在的行 | 原构造遍历兼容版；新的原始输入夹具包含这类记录 | 原生版保留所有选中观测，CPU 缺失仅从配对视图排除并计数 |
| P2 | 查询导入 `tsdb`，构造需要 `--v1`／`--repo` | 原调用链直接导入主项目的 `instantiate_tsdb_query` | 本包保存独立声明式查询合同；迁移对照 1,200 组参数组合 |
| P2 | 外部符号链接和绝对映射路径导致搬迁后失效 | 原 compatible 通过符号链接引用 v1 | 新输出全是实际文件；映射和数据文件路径相对 bundle，验证原始输入显式传入 |
| P2 | 机器数固定 1000，时间固定第一天；规模配置与数组结构耦合 | 原数组和循环直接写常数 | 映射长度决定最大机器数；支持显式规模集合与零基日窗口；一天十秒网格作为公开格式范围 |
| P2 | 构造失败留下已创建但不完整的目录 | 原程序在扫描前创建输出根目录 | 临时目录构造后发布，失败留独立诊断；测试确认目标未发布 |
| P2 | 无参数 Q1 反复出现，容易被当作独立样本 | 原每类固定写 20 条，Q1 参数完全相同 | 保持种子集合并去除重复 SQL，四个 SF 各 281 条 |
| P2 | 最新点形状按照声明主机数计算，包含无有效 CPU 观测的机器 | 独立夹具中两台选中机器仅一台有 CPU 数据 | 按实际存在的有效 CPU 主机数计算 |
| P2 | 数据库回读先标记通过，清理失败仍可能留下通过报告 | 新测试模拟 DROP 失败，先观察报告错误地 passed | 清理错误改为 failed，并保留 `cleanup_error` |

## 验证设计

单元和集成契约使用独立给定的原始行、完整参考键和确定的期望结果，不从被测编码器生成所有期望。源值篡改、同时修改两侧、空查询、重复源键、窗口平移、缺失 CPU、目录搬迁、全局 RNG 状态、查询投影以及清理失败均有独立可选 pytest 用例。

测试输入及输出全部由临时目录拥有，成功和失败后都清理。只有外部数据库边界的清理失败使用模拟，关键数据文件、源比对和搬迁使用真实文件。

真实数据构造和验证重新扫描独立项目中的约 9 GB CSV，检查 SF1／10／100／1000。具体结果保存在 `data/alibaba_day1/validation_runs/`，数据库回读记录在 `oracle_runs/`。安装包不包含大数据文件。

## 保持不变的研究限制

- 第一天真实样本中两个指标全缺失；不能生成虚构的观测填满它们。
- 真实缺测使行数小于稠密 TSBS，原主项目的 8,000 行／机器门槛仍需独立处理。
- 原生 schema 与兼容 schema 是不同负载。不能仅因数据项目独立，就直接复用原 C++ 引擎读取原生版。
- 桶对齐和排序现在写入 SQL，而非依赖数据库默认值；这是新的查询版本。历史实验参数保持一致，但不能将历史旧 SQL 与新 SQL 未经说明混合计时。
- 没有执行任何新的性能基准，也没有公开发布仓库或第三方数据。

## 独立性验收标准

1. 运行依赖只有 NumPy，没有 LLM、W&B、原 `tsdb` 包或主项目路径注入。
2. 可使用自己的 `uv.lock` 安装，并构建标准 wheel／sdist。
3. 构造仅需要明确的 CSV、映射和 TSBS 参考输入，不需要先存在一个 v1 数据集。
4. 数据目录搬迁后，通过显式原始输入继续校验。
5. 大数据放在 Git 忽略目录；复制代码和复制完整数据项目的操作边界在 README 中说明。

## 本次实际验收结果

- 11 个 pytest 契约用例通过，临时测试数据自动清理。
- SF1／10／100／1000 全量重建，并逐值对照独立项目中的原始 CSV 和 TSBS 文件通过。
- [查询参数迁移](query_migration_check.json)：1,200 组组合保留原参数语义。
- [实际查询检查](query_execution_check.json)：SF1 的 281 条去重 SQL 全部执行，返回行数与目录记录一致。此检查不证明全部指标值或所有规模的查询语义均已执行验证。
- [独立安装检查](package_verification.json)：wheel 安装到临时干净环境，运行不依赖源码 checkout；在其他工作目录构造小数据、搬迁后校验，并用真实 QuestDB 回读包含缺失 CPU 的原生记录。
- 所有临时数据库表已清理，旧项目工作区保持不变。
- 实际测试环境为 macOS arm64、Python 3.14.6。Python 3.11+ 是代码声明支持范围，其他系统和解释器组合尚未逐一执行测试。

wheel 只包含运行代码；sdist 还包含锁文件、测试及小型来源说明，不包含大体积原始 CSV 或 ILP。独立安装检查允许从包索引安装锁定依赖，不作离线安装保证。
